# Languages: English and Bangla (0A.10)

Plan: Ch 13 (13.2, 13.8 #1, #8), Ch 8.9 rules 1–2, Ch 48.7, Ch 47.8. Decision D13: the whole UI in Bangla and
English; each person picks, the institution sets the default.

## Rules

1. **Every user-visible word comes from a translation file.** No text in JSX, `title=` / `placeholder=` /
   `accessibilityLabel=` props, navigation options or alerts. `npm run check:i18n` fails otherwise.
2. **Every key exists in both languages**, with the same `{{placeholders}}`. CI fails on a key in one language only.
3. **Renamable terms never appear in translations or code** ("Student", "Course", "Admission", "শিক্ষার্থী", "ভর্তি" …).
   They come from labels (0A.12), which each institution can rename (Ch 8). Write "Add {{client}}" instead.
4. **Terms follow the glossary**: `docs/dev/GLOSSARY.md`. One English word on a Bangla screen (or the reverse)
   makes the app look half-translated (Ch 13.8 #1).
5. **Bangla texts are read by a native reader before each release** (release rule 8 in
   `ENVIRONMENTS_AND_RELEASES.md`).

## How to add text

```tsx
import { useTranslation } from '@/i18n';
import { AppText } from '@/components/AppText';

const { t } = useTranslation('language');           // namespace = feature
<AppText>{t('current', { language: t('names.bn') })}</AppText>
```

1. Add the key to `src/i18n/locales/en/<namespace>.json` **and** `src/i18n/locales/bn/<namespace>.json`.
2. Keys are typed: `t('typo')` fails `npm run typecheck`.
3. New namespace (one per feature, e.g. `leads`, `followups`): add the JSON file for every language and list it in
   `src/i18n/resources.ts`.
4. Use `AppText` (not React Native's `Text`) so Bangla gets the Bangla font.
5. Server errors: `useErrorText()` from `@/i18n/errors` turns the error contract's `messageKey` and `action` into
   text. A new error code in `supabase/functions/_shared/errors.ts` must be translated (the check enforces it).

Exemptions are rare and need a reason on the line: `// i18n-exempt: brand name, never translated`. A developer-only
file can be exempted with `// i18n-exempt-file: <reason>`.

## Which language is shown

Same rule in the app (`src/i18n/language.ts`) and the database (`app.resolve_language`):

**the person's choice → the institution's `default_language` setting → English.**

| Moment | Source |
|---|---|
| App start (first paint) | The last language used on this device (AsyncStorage), else English |
| Right after sign-in, institution switch, token refresh | `my_language()` from the server |
| The person picks a language | `set_my_language(lang)` (or `null` = follow the institution); the UI switches at once, before the server answers, and switches back if the call fails |
| The institution changes its default | Settings version rises → followed by everyone who has no own choice |
| Not signed in | The choice is kept on this device only |

Switching uses `i18n.changeLanguage()`: every mounted screen re-renders, no reload or restart (tested on the web
build by `npm run test:ui`; Android flow in `.maestro/language-switch.yaml`).

## Font

Bangla uses **Noto Sans Bengali** (`@expo-google-fonts/noto-sans-bengali`, regular 400 and semibold 600), loaded in
`src/app/_layout.tsx` before the first screen, so conjuncts and vowel signs render the same on every phone and
browser. English uses the system font. `AppText` picks the font from the current language.

## Message templates are different (0A.10-T7, built in 1B, Ch 24)

The language of an SMS, email or WhatsApp message follows **the recipient** (the lead's or contact's language,
else the institution's default), **never the language of the staff member's screen**. A counsellor using the app in
English still sends a Bangla SMS to a Bangla-speaking lead. Templates are stored per language; sending picks the
recipient's.

## Adding a third language later (Ch 13.2, Ch 53)

1. Add the language code to `SUPPORTED_LANGUAGES` (`src/i18n/language.ts`).
2. Add a folder `src/i18n/locales/<code>/` with every namespace (the check lists what is missing).
3. Allow the code in the database: `profiles.preferred_language` check, `set_my_language`, and the
   `default_language` setting schema (a new migration).
4. Add a font if the script needs one; add glossary rows.
