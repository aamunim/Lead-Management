# Neutral keys and the label dictionary (0A.12)

Plan: Ch 8 (8.1–8.11), Ch 2.3 principle 13, Ch 43.4 #8. Decisions D13, D18, D20. Migrations
`20261110210000_labels.sql`, `20261110210100_label_seed.sql` (generated by `scripts/labels/gen_label_seed_0A12.py`).

**Internal keys are business-neutral and never change. What people see is a label, which every institution can
rename in English and Bangla. Renaming never needs a code change or a migration.**

## Layers

**institution → type profile (0B) → pack → product.** Education is the only pack for now (D20); the Ch 8.5
examples (school, university, polytechnic) are stored as profile defaults and wired to type profiles in 0B
(`app.institution_label_scopes()` is the hook). The product layer holds neutral words for any business.

Module names follow their base word (`module.clients` → plural of `client`) unless renamed on their own.

## Words, forms and length

- English: singular and plural. Bangla: `base`, `plural`, `possessive`, `objective`, `plural_oblique`, generated
  from the base by `app.bn_forms()` (people take রা / র / কে / দের; things take গুলো / র / গুলোর; possessive is
  র after a vowel, ের after a consonant, -এর after Latin letters). Any form can be overridden by hand.
- Every key has a `max_length` (Ch 8.8): longer words are refused (`label_too_long`).
- `lockable` keys (printed titles) can be locked by the platform (`label_lock`); the institution then cannot change
  or reset them (`label_locked`).

## Server

| Function | Does |
|---|---|
| `public.labels_get()` | all words of the active institution: resolved, the default underneath, the product word |
| `public.label_set(key, en_singular, en_plural, bn_forms, institution?)` | rename (permission `settings.terminology`; Master Admin until 0A.17); audited, event `label.changed`, bumps the settings version so every device refreshes |
| `public.label_reset(key, institution?)` | back to the default |
| `public.label_lock(institution, key, locked)` | platform only |
| `app.label(institution, key, language, form)` | one word for notifications, prints and AI prompts (later milestones) |

## App

- The `labels` i18n namespace holds the words. **In sentences:** `"Add $t(labels:client.singular)"`,
  `"সব $t(labels:client.plural_oblique) তালিকা"`. **In code:** `label('client', 'plural')` from `@/lib/labels`.
- Write so the label stands alone where possible ("শিক্ষার্থী: ২৫", Ch 8.7). Use the Bangla forms instead of adding
  endings in the sentence (never `{{client}}দের`).
- Bundled defaults (`src/i18n/locales/*/labels.json`, `src/i18n/label-meta.json`) are generated from the database
  (`npm run labels:export`); CI fails if they drift (`npm run check:labels`). After sign-in, `labels_get()` replaces
  them; a rename reaches every device on its next request (settings version).
- Search: `searchLabels(query, toSearchable(entries))` from `@/lib/label-search` matches the current word, the
  default and product words and the key / old key, in both languages ("student" finds a module called "Trainees").
- `check:i18n` fails on a `$t(labels:…)` that does not exist, on a missing Bangla form, and on renamable words
  written directly into translations or code.

## Rules for every later feature (0A.12-T9)

1. Every new user-visible word that an institution might call differently is **added to the label list before
   release** (new migration: `label_keys` + product and pack defaults; then `npm run labels:export`).
2. Tables, columns, RPCs, API fields, event names, template variables and export technical names use the
   **neutral key** and never change when a label changes (Ch 8.9 rule 3, Ch 8.10 #6).
3. Screenshot tests run with the **weird-labels institution** (`test-weird-labels`, user `weird.member@example.test`)
   in both languages (Ch 8.9 rule 4).
